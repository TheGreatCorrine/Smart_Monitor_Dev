# 系统功能说明文档

## 🎯 核心功能概述

Smart Monitor and Alert System 是一个智能监测报警系统，具备以下核心能力：

- **智能监测**: 实时数据监控和异常检测
- **自动告警**: 智能规则引擎驱动的告警系统
- **多界面支持**: CLI、GUI、Web三种交互方式，未来开发方向将以Web为主，CLI和GUI更多用于测试开发，仅具备基础功能。
CLI位于 `backend/app/cli.py`
GUI位于 `backend/app/gui.py`
Web目前有一个目录`web/`，调用了backend里许多模块的逻辑，是重点开发方向，这部分开发时间比较紧急，主要用于汇报展示。
理论上上线时应当移除cli和gui版本，并重构web模块至`frontend`以及`backend`
- **灵活配置**: 可配置的监测规则和通道设置

## 🚀 主要功能模块

### 1. 数据监控模块
- **实时数据采集**: 数源（data source）为Central PC (server). `.dat`文件从Central PC传输过来，输送到这个软件部署的server上。\
(具体数据传输流程和data flow见[系统架构说明](docs/ARCHITECTURE.md))
- **数据解析**: `DatParser Service`能智能解析二进制数据文件(`.dat` files are encoded, binary files) \
(二进制加密解析规则由SigmaData提供：[Sigmadata提供数据管道文件](SigmaData_DatParser.xlsx))

### 2. 配置管理模块
- **通道标签匹配**: 用户可自由选择标签(label)和数据通道(channel)的匹配，用于后续规则判断以及告警
    - **Channel（数据通道）**: 硬件层面的数据采集点，如温度传感器(Temperature Sensor)、压力传感器(Pressure Sensor)等，从`.dat`文件直接读取的原始数值，在[`label_channel_match.yaml`](../config/label_channel_match.yaml)里定义为T1-T22、TE1-TE14、DE1-DE14等通道标识
    - **Label（标签）**: 业务层面的含义标识，如TR、TFC、TVFC、VFC evap sensor等等，是用户（测试工程师们）会在sigmadata里手动填写，帮助他们理解数据的业务含义，同时也用于规则判断引擎(Rule Engine)
    - **匹配目的**: 建立Channel和Label的对应关系，将硬件采集的原始数据(T1-T22、TE1-TE14、DE1-DE14)转换为有意义的业务标签(TR、TFC、TVFC等)，使测试工程师能够理解数据含义，并为**规则判断引擎**(Rule Engine)提供业务逻辑基础，实现智能告警和异常检测 
- **规则配置**: 可自定义的监测规则，暂未实现
- **系统配置**: 系统参数和环境配置，暂未实现

### 3. 告警系统模块
（该模块暂未实现，需等技术评估之后，确定白名单可以放行的软件后实现，预计代码量极小）
- **智能告警**: 基于pre-configured rules: [`rules.yaml`](../config/rules.yaml)配置规则的智能告警触发
- **告警分级**: 支持不同级别的告警分类（目前有4个级别：Low、Medium、High、Critical）
- **告警通知**: 多种通知方式（弹窗、邮箱、企业微信、手机短信推送等）
- **告警历史**: 完整的告警记录和统计（可以在dashboard上看到）
